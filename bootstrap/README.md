# AI Lab — запуск с USB: S0 → S1

**Инструкция для оператора.** Начните здесь на новой машине, не требуется помнить
команды из чата. Проверенная платформа: Ubuntu 24.04 Desktop, amd64, VMware.
S0 восстанавливает прокси и Git; S1 настраивает доступ к GitHub и проверяет хост.
**S1 пока кандидат в PR #5, а не завершённая инфраструктура.**

## 0. Подготовить флешку на доверенной машине (до развёртывания)

Копируйте **весь каталог `bootstrap/`**, не переименовывая папки.
На флешке должны быть:

```text
USB/
└── bootstrap/
    ├── README.md                     ← вы здесь
    ├── stage0/
    │   ├── bootstrap.sh              ← запускается первым
    │   ├── README.md
    │   ├── proxy/
    │   └── private-proxy/            ← приватные файлы, НЕ в Git
    │       ├── README.md
    │       ├── v2rayN-linux-64.deb
    │       ├── v2rayn-data.tar.gz
    │       └── v2rayn-data.sha256
    └── host/
        ├── bootstrap.sh
        └── README.md                 ← детали S1
```

Три файла в `private-proxy/` берутся из **защищённого локального хранилища**,
а не из GitHub. Их подготовка: [private-proxy/README](stage0/private-proxy/README.md).
В них есть секреты: не выкладывайте наполненную флешку или архив в Git.
**После изменения репозитория флешка сама не обновляется.** На доверенной
машине перейдите на проверяемую версию Git (пока PR #5 открыт —
`feat/s1-host-ssh-transport`) и обновите содержимое USB, например:

```bash
cd ~/projects/ai-lab
USB="/media/$USER/ИМЯ_ФЛЕШКИ"  # замените на фактическую точку монтирования
mkdir -p "$USB/bootstrap"
cp -a bootstrap/. "$USB/bootstrap/"
test -f "$USB/bootstrap/README.md"
test -f "$USB/bootstrap/stage0/bootstrap.sh"
```

Это **копирование с сохранением существующих файлов**, а не очистка
каталога: приватные файлы в `USB/bootstrap/stage0/private-proxy/`
не должны удаляться. Не применяйте `rsync --delete` к этой папке.
Проверьте, что три приватных файла на месте перед запуском S0.

## 1. На чистой Ubuntu — запустить S0 с USB

Подключите флешку. Чтобы узнать путь (метка флешки отличается на машинах):

```bash
find "/media/$USER" -type f -path '*/bootstrap/stage0/bootstrap.sh' -print
```

Запустите найденный файл, **подставив фактический путь**, например:

```bash
bash "/media/$USER/ИМЯ_ФЛЕШКИ/bootstrap/stage0/bootstrap.sh"
```

Что происходит: офлайн установка v2rayN, восстановление прокси, настройка
автозапуска, APT и Git, затем клонирование репозитория в
`~/projects/ai-lab`. **При запросе скрипта откройте v2rayN в GNOME,
выберите рабочий сервер и дождитесь запуска Xray, только потом нажмите Enter.**
Это обязательное ручное действие для первого запуска.

Продолжайте **только** после сообщения `Stage 0 PASS`.
При ошибке остановитесь и исправьте её; не переходите к S1.

## 2. Перейти в каталог кода (после S0)

```bash
cd ~/projects/ai-lab
```

**Временное действие, пока PR #5 не слит в `main`:** поскольку S0 клонирует
принятый `main`, в нём может не быть Makefile и S1. Если файла `Makefile` нет,
подключите тестовую ветку:

```bash
if [[ ! -f Makefile ]]; then
  git -c http.proxy=http://127.0.0.1:10808 \
    fetch origin feat/s1-host-ssh-transport
  git switch --track origin/feat/s1-host-ssh-transport
fi
```

После принятия PR #5 в `main` этот временный блок будет не нужен.
Не считайте содержимое открытого PR принятой реализацией.

## 3. Установить инструменты S1 и проверить повторный запуск

В S0 `make` ещё может отсутствовать, поэтому **первый раз используйте Bash**:

```bash
bash bootstrap/host/bootstrap.sh
```

Далее используйте единый интерфейс:

```bash
make help
make host-setup
make host-setup
make host-test
```

Ожидается `S1 local config and proxied HTTPS: PASS` и **две строки `PASS`**
от `make host-test`. Повторный `host-setup` не должен повреждать настройки.

## 4. Авторизовать SSH в GitHub

```bash
make github-setup
```

Мастер проверит существующий SSH-ключ; **новый создаст только после
подтверждения**. При создании рекомендуется задать passphrase. Мастер
показывает **только публичный ключ**, пытается скопировать его в буфер
обмена и открыть https://github.com/settings/keys. Добавьте **публичный**
ключ в GitHub: `New SSH key` → `Authentication Key`. Затем нажмите Enter
в терминале для проверки (или введите `skip` и проверьте позднее).

Перед первым подтверждением подлинности SSH-сервера сравните показанный
отпечаток с [официальными отпечатками GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints).
Не подтверждайте несовпадающий ключ; мастер не отключает эту проверку.
Если браузер не открывает GitHub, его прокси нужно настроить отдельно;
успешная работа APT и терминала этого не гарантирует. Если буфер обмена
недоступен, просто скопируйте текст публичного ключа.

После регистрации ключа (если пропустили проверку в мастере):

```bash
make github-verify
make host-verify
```

Ожидается сообщение GitHub об успешной аутентификации и
`S1 GitHub SSH authentication: PASS`. Ответ GitHub `does not provide shell
access` — **нормальный**, у GitHub нет интерактивной SSH-оболочки.

## 5. Перезагрузить и повторить проверку

```bash
sudo reboot
```

После входа в GNOME **не запускайте v2rayN вручную**, чтобы проверить
автозапуск. Затем:

```bash
cd ~/projects/ai-lab
make host-verify
make github-verify
```

Обе проверки должны пройти. Если прокси требует ручного запуска после
перезагрузки, это дефект/ограничение, а не успешная проверка автозапуска.

## Если что-то не сработало

- Не найдены скрипты или приватные файлы: проверьте **структуру USB**
  и [требования S0](stage0/README.md).
- `Stage 0 PASS` отсутствует: сначала исправьте S0.
- Нет `make`: выполните `bash bootstrap/host/bootstrap.sh` из каталога
  репозитория после S0.
- SSH не авторизуется: проверьте регистрацию **публичного** ключа,
  правильность отпечатка сервера и `make host-verify`.
- Для диагностики и подробностей используйте [S1 README](host/README.md).
  Статус и результаты испытаний фиксируются в
  `docs/project/state.md` в репозитории.

**Безопасность:** приватные SSH-ключи не отправлять в чат и Git;
`private-proxy` не публиковать. Откат снимка VMware может уничтожить
новый SSH-ключ — сохраните его защищённо либо создайте новый и отзовите
старый ключ в GitHub. S1-D/Docker и AI-компоненты здесь ещё не устанавливаются.
