# Закрытие эксперимента Codex → n8n MCP (2026-10-22)

**Статус: функциональная гипотеза Stage A подтверждена по отчёту оператора; сохранение первичных артефактов и очистка VM ещё НЕ завершены.** Этот документ относится только к экспериментальному [PR #11](https://github.com/lehater/ai-lab/pull/11); **не сливать экспериментальную инфраструктуру с main**.

## Что действительно установлено

По [операторскому отчёту в PR #11](https://github.com/lehater/ai-lab/pull/11) и ранее зафиксированным логам:

- На `lab-test` работали Codex CLI `0.163.0`, аутентификация через ChatGPT, n8n `2.44.5` в отдельном локальном Docker Compose и MCP discovery/read.
- Создан workflow `AI Lab MCP Spike - multiply` (`0MfgOrrQXujdLHVM`); запуск № 1 вернул `{"value":8}` при множителе 2.
- После отвергнутого некорректного пути изменения массива workflow изменён через `updateNodeParameters`; оператор сообщил, что запуск № 2 вернул `{"value":12}` при множителе 3 в **том же workflow**. Черновик не публиковался.
- После установки узкоспециализированного профиля AppArmor `bwrap-userns-restrict` при сохранённом глобальном ограничении `kernel.apparmor_restrict_unprivileged_userns=1`, команда `codex sandbox -- /bin/true` завершилась с кодом 0; отдельная интерактивная read-only проверка также отмечена как PASS в PR.

**Граница доказательств:** выполнение Stage A описано оператором/Codex, но полные локальные JSON-артефакты не проверены независимо и не находятся в удалённой ветке. Исторический [stage-a-operator-report](evidence/2026-10-22-stage-a-operator-report.md) первоначально содержит *partial* состояние и служит хронологией ошибок, а не последним статусом. Не превращать это в утверждение о полном Git-based export/replay или восстановлении n8n на чистом томе — **Stage B не выполнялся**.

**Инженерный результат:** Codex способен через MCP изменять и выполнять workflow в n8n, но для простого детерминированного преобразования `4 × 2/3` сам n8n не даёт доказанного преимущества перед скриптом. Поэтому **не вводить n8n в инфраструктурное ядро AI Lab и не продолжать Stage B без нового потребителя**. Полезный переносимый результат — установка Codex, проверка sandbox/AppArmor, работа с MCP и безопасные ограничения привилегий. Не добавлять Codex в Docker group.

## Минимальная процедура: сохранить доказательства без VMware snapshot

Выполнить **в обычном терминале Ubuntu, не в Codex**. Это чтение; никакого `git fetch/pull/switch/reset/clean` на первом шаге:

```bash
cd ~/projects/ai-lab
printf 'branch: '; git branch --show-current
git status --short --branch
git diff --stat -- docs/project/state.md
d=experiments/workflow-automation-n8n/evidence/2026-10-22-stage-a
if test -d "$d"; then
  find "$d" -maxdepth 1 -type f -printf '%f\n' | sort
  for f in "$d"/*.json; do
    test -f "$f" || continue
    python3 -m json.tool "$f" >/dev/null && echo "JSON valid: ${f##*/}" || echo "JSON INVALID: ${f##*/}"
  done
else
  echo 'LOCAL STAGE A EVIDENCE DIRECTORY NOT PRESENT'
fi
```

Этот вывод содержит **только имена файлов, состояние Git и валидность JSON**, не содержимое workflow или токены. Если есть незнакомые изменения или данные не на месте — **остановиться, не удалять/переключать ветку**.

Далее следует локально проверить содержимое JSON и README (включая все metadata-поля) на bearer/API tokens, credentials, URL с секретами, персональные данные и ненужные идентификаторы. `python3 -m json.tool` проверяет лишь синтаксис и **не** является проверкой отсутствия секретов. При необходимости вместо сырого экспорта сохранить **редактированную** версию с явным указанием удалённых полей. Подтвердить, что `workflow-before.json` и `workflow-after.json` действительно относятся к одному workflow, а `results.json` содержит два требуемых исполнения. Если данные неполные — обозначить это, не создавать вымышленные артефакты.

После проверки и согласования локального изменения `docs/project/state.md` выполнить адресное сохранение **только четырёх отобранных артефактов**, не `git add .`; не публиковать данные, пока их безопасность не проверена. Если рабочая ветка расходится с удалённой, сперва сохранить локальные изменения и согласовать Git integration, **не использовать `reset --hard` или `clean`**. После push проверить, что файлы доступны по ссылкам GitHub в PR #11.

## Остановка и очистка — только после сохранения нужных данных

- Не нужно делать промежуточный VMware snapshot ради обычного закрытия PR. Но отсутствие snapshot означает, что **несохранённые файлы и Docker volume будут безвозвратно потеряны при очистке/откате**.
- После подтверждения сохранения нужных артефактов можно выполнить `bash experiments/workflow-automation-n8n/lab.sh stop` (объём данных **остаётся**) или, при явном согласии уничтожить экспериментальные данные, `bash experiments/workflow-automation-n8n/lab.sh clean --destroy-experiment-data` (удаляет проектный контейнер, volume, сеть и локальный ключ). **Не запускать `clean` до подтверждения.** Не выполнять `docker system prune` / `docker volume prune`.
- `lab.sh clean` **не удаляет Codex, Node.js/npm, AppArmor, `~/.codex` или установленный профиль MCP**. Эти компоненты следует рассматривать отдельно от удаления n8n. Удаление токена/ключа доступа MCP после окончания эксперимента и удаление записи `[mcp_servers.ai_lab_n8n_spike]` из `~/.codex/config.toml` — отдельные управляемые оператором действия. Никогда не коммитить `~/.codex/auth.json`.
- Для проверки Ansible нет необходимости удалять Codex или AppArmor. Первый функциональный Ansible spike можно провести на существующей VM; **проверка чистого развертывания** проводится позже на известном baseline, без подмены доказательств.
